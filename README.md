# margot

## Usage

Add margot CLI to your project as a dev dependency

```sh
gleam add margot --dev
```

Create one `<locale>.i18n.yaml` file per language in a `lang` directory at the root of your project next to `gleam.toml` :

```text
├── gleam.toml
├── lang
│   ├── en.i18n.yaml
│   └── fr.i18n.yaml
└── src
    └── app.gleam
```

```yaml
# lang/en.i18n.yaml
home:
  title: "Welcome back!"
  greeting: "Hello {name}"
  unread_messages:
    one: "You have {n} unread message"
    other: "You have {n} unread messages"

buttons:
  save: "Save"
  cancel: "Cancel"
```

```yaml
# lang/fr.i18n.yaml
home:
  title: "Bon retour !"
  greeting: "Bonjour {name}"
  unread_messages:
    one: "Vous avez {n} message non lu"
    other: "Vous avez {n} messages non lus"

buttons:
  save: "Enregistrer"
  cancel: "Annuler"
```

Then run the margot module with the following :

```sh
gleam run -m margot
```

And it creates the `src/t.gleam` file for you, defining :

- the `t.Locale` enum with one variant per locale (`t.En` and `t.Fr` here)
- `t.auto_()` which auto-detects the user locale for you
- one function per translation taking the locale as its first argument and after your parameters (`t.buttons__save(locale)`)

```text
├── gleam.toml
├── lang
│   ├── en.i18n.yaml
│   └── fr.i18n.yaml
└── src
    ├── app.gleam
    └── t.gleam  <- generated
```

```gleam
import t

pub fn main() {
  let locale = t.auto_() // on JS it auto-detects the user language, otherwise it falls back to the default one
  // let locale = t.Fr // or pick one yourself

  echo t.buttons__save(locale) // basic
  echo t.home__greeting(locale, name: "Margot") // parameters
  echo t.home__unread_messages(locale, n: 3) // pluralization
}
```

The name of a function is the path of the translation in the YAML file with the keys joined by `__` (`home.greeting` becomes `t.home__greeting`).

A missing translation is only a **warning** (margot falls back to the default locale) but a missing parameter, or one of the wrong type, is an **error**.

## CLI

| Command                     | Description                                           |
|-----------------------------|-------------------------------------------------------|
| `gleam run -m margot`       | Generate the Gleam files from the translation files   |
| `gleam run -m margot watch` | Rebuild automatically when a translation file changes |

## Configuration

By default margot generates the `src/t.gleam` file. You can change where it is generated by adding a `[tools.margot]` table to your `gleam.toml`.

```toml
[tools.margot]
output = "src/app/i18n.gleam"
```

The name of the file is the name of the module so here `src/app/i18n.gleam` is imported with `import app/i18n` and must be a valid Gleam module name (lowercase and `_`).
The path can go outside of the project root using `..`, missing directories are created.

The JavaScript file used to detect the user locale is generated next to the module and is named after it (`src/app/i18n_ffi.mjs` here).

```text
├── gleam.toml
├── lang
│   ├── en.i18n.yaml
│   └── fr.i18n.yaml
└── src
    └── app
        ├── i18n.gleam      <- generated
        └── i18n_ffi.mjs    <- generated
```


Personally, and this is just my opinion, I find a `t` module faster to memorize and use, but do as you please.

## Main Features

### Parameter

Translations often have dynamic parameters. Wrap the name of a parameter in braces `{name}`.

You can always escape them by adding a backslash `\\{notAnArgument}`.

Each translation has its own parameters. They become the **labelled arguments** of the generated function after the locale.

```yaml
hello: "Hello {name}. I am {height}m."
```

```gleam
let s = t.hello(locale, name: "Margot", height: "1.80") // Hello Margot. I am 1.80m.
```

By default every parameter is a `String` except the parameter `n` which is an `Int` since it's often used for pluralization (see [Pluralization](#pluralization)).

You can specify the type using the `{name: Type}` syntax.
Supported types are `String`, `Int` and `Float`.

```yaml
greet: "Hello {name}, you are {age: Int} years old"
```

```gleam
// fn(Locale, name: String, age: Int) -> String
let s = t.greet(locale, name: "Margot", age: 23)
```

When a translation uses the same parameter name several times, the same value is used for all of them.
If two locales use the same parameter with different types generation fails.
The same goes for parameters coming from a linked translation (see [Linked Translations](#linked-translations)).

### Linked Translations

You can link one translation to another. Add `@:{path}` with the **absolute** path of the desired translation.

```yaml
fields:
  name: "my name is {first_name}"
  age: "I am {age} years old"
introduce: "Hello, @:{fields.name} and @:{fields.age}"
```

```gleam
let s = t.introduce(locale, first_name: "Margot", age: "23") // Hello, my name is Margot and I am 23 years old.
```

The parameters of the linked translations are added to the ones of the translation so `first_name` & `age` become `first_name, age`.

Parameters coming from linked translations are merged as if they were a single translation. This means the rules about not mixing parameter types apply, and parameters with the same name share a single value.

```yaml
first: "Hi {name}"
second: "Bye {name}"
both: "@:{first}, @:{second}"
```

```gleam
let s = t.both(locale, name: "Margot") // Hi Margot, Bye Margot
```

To avoid repeating long paths you can use a **relative** path by using a single dot like that `@:{.path}`.
The link is then resolved against the siblings of the current translation.

```yaml
remaining_time:
  hours_unit: "{h}h"
  minutes_unit: "{m}m"
  hours: "@:{.hours_unit} @:{.minutes_unit}"
```

```gleam
let s = t.remaining_time__hours(locale, h: "2", m: "30") // 2h 30m
```

Each additional dot goes up one level, like relative imports in Python : `@:{..path}` is resolved against the parent group, `@:{...path}` against the grandparent and so on.
Going above the root is an error.

```yaml
first:
  floor: "first floor"
  other:
    floor: "other floor"
  second:
    floor: "second floor"
    parent: "@:{..floor}"       # first floor
    cousin: "@:{..other.floor}" # other floor
```

Optionally you can escape linked translations by using a backslash :

```yaml
fields:
  name: "my name is {first_name}"
introduce: "Hello, \\@:{fields.name}inator"
```

### Pluralization

Handling plurals in translations makes your sentences richer and more natural for the end user.
This follows the CLDR concept defined [here](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html) of placing different quantities inside categories.
Those categories are defined with the following keywords: `zero`, `one`, `two`, `few`, `many`, `other`.

Some languages are supported out of the box (`ar`, `cs`, `de`, `en`, `es`, `fr`, `he`, `id`, `it`, `ja`, `ko`, `ms`, `pl`, `pt`, `ru`, `sv`, `th`, `uk`, `vi` and `zh`).
Languages not yet supported will just use `zero`, `one` and `other`.

```yaml
# lang/en.i18n.yaml
some_key:
  apple:
    one: "I have {n} apple."
    other: "I have {n} apples."
```

```gleam
let a = t.some_key__apple(locale, n: 1) // I have 1 apple.
let b = t.some_key__apple(locale, n: 2) // I have 2 apples.
```

Plurals are **cardinals** by default.

To specify ordinals you need to add the `(ordinal)` modifier at the end of the key.
When doing linked translations the modifier is not applied in the key path (`@:{some_key.place}`).

```yaml
# lang/en.i18n.yaml
some_key:
  apple(cardinal): # cardinal
    one: "I have {n} apple."
    other: "I have {n} apples."
  place(ordinal): # ordinal (rarely used)
    one: "{n}st place."
    two: "{n}nd place."
    few: "{n}rd place."
    other: "{n}th place."
```

Inside your plurals you can add as many parameters as you want.

```yaml
playlist_track_count:
  one: "\"{name}\" has {n} track."
  other: "\"{name}\" has {n} tracks."
```

```gleam
let a = t.playlist_track_count(locale, n: 2, name: "Road trip") // "Road trip" has 2 tracks.
```

As said, the plural is driven by `n` by default. Add `=name` to the modifier to target another parameter instead :

```yaml
apple(cardinal=count):
  one: "I have {count} apple."
  other: "I have {count} apples."
place(ordinal=rank):
  one: "{rank}st place."
  other: "{rank}th place."
```

```gleam
let a = t.apple(locale, count: 2) // I have 2 apples.
let b = t.place(locale, rank: 1) // 1st place.
```

To use multiple different plurals in the same sentence you can use [Linked Translations](#linked-translations).
Parameters with the same name are merged, so by default the plurals share the same `n` :

```yaml
apples:
  one: "one apple"
  other: "{n} apples"
bananas:
  one: "one banana"
  other: "{n} bananas"
sentence: "I have @:{apples} and @:{bananas}"
```

```gleam
let s = t.sentence(locale, n: 2) // I have 2 apples and 2 bananas
```

Give each plural its own parameter to make them independent :

```yaml
apples(cardinal=apple_count):
  one: "one apple"
  other: "{apple_count} apples"
bananas(cardinal=banana_count):
  one: "one banana"
  other: "{banana_count} bananas"
sentence: "I have @:{apples} and @:{bananas}"
```

```gleam
let s = t.sentence(locale, apple_count: 1, banana_count: 2) // I have one apple and 2 bananas
```

A key must be a plural in **every** locale.

## Other Features

### Region Extensions

You can extend a language-only locale (e.g. `en`) with region-specific locales (e.g. `en-US`, `en-GB`).

It **always** falls back to the language-only locale so a region file only contains what differs.
A language-only locale falls back to the default locale with a warning for each missing key.
The default locale is `en` when it exists, otherwise the first locale in alphabetical order.

It synergizes well with [Wildcard Locales](#wildcard-locales).

```text
en.i18n.yaml
en-US.i18n.yaml -> en.i18n.yaml
en-GB.i18n.yaml -> en.i18n.yaml
fr.i18n.yaml -> en.i18n.yaml (default locale, warns on missing keys)
fr-CA.i18n.yaml -> fr.i18n.yaml
```

Variants of `t.Locale` are named in PascalCase: `en-US` becomes `t.EnUs`.

### Wildcard Locales

Reuse the same translations for multiple locales.

A locale can come from several files. When they define the same translation the first one wins in this order:

1. the file named after the locale (`de.i18n.yaml`)
2. the wildcards with codes (`[de,fr,ja].i18n.yaml`)
3. the wildcards with `any` (`[any]-FR.i18n.yaml`)

It works well with [Region Extensions](#region-extensions).

| Syntax          | Description                                    |
|-----------------|------------------------------------------------|
| `[de,en,fr-FR]` | Spreads to the specified codes                 |
| `[any]`         | Spreads to all existing codes in that position |

`[any]` at the start of a name is every existing language and `[any]` after a `-` is every existing region :
- `[any]-FR` spreads to every language, `en-[any]` spreads to every region.

Scripts (`Hant` in `zh-Hant-TW`) are never spread and an `[any]` without any existing code is a warning.

```text
lang/
 ├── de.i18n.yaml
 ├── en.i18n.yaml
 ├── fr.i18n.yaml
 ├── [de,fr,ja].i18n.yaml
 └── [any]-FR.i18n.yaml
```

This will spread to the following locales:

| Locale  | Source                                 |
|---------|----------------------------------------|
| `de`    | `de.i18n.yaml`, `[de,fr,ja].i18n.yaml` |
| `en`    | `en.i18n.yaml`                         |
| `fr`    | `fr.i18n.yaml`, `[de,fr,ja].i18n.yaml` |
| `ja`    | `[de,fr,ja].i18n.yaml`                 |
| `de-FR` | `[any]-FR.i18n.yaml`                   |
| `en-FR` | `[any]-FR.i18n.yaml`                   |
| `fr-FR` | `[any]-FR.i18n.yaml`                   |
| `ja-FR` | `[any]-FR.i18n.yaml`                   |

### Sanitization

All keys and parameter names must be valid Gleam identifiers. Otherwise margot will automatically sanitize them.

The suffix `_` is added if the generated function name, or a parameter name, is one of the Gleam keywords (`import`, `type`, `case`, `fn`, `use`, `auto`, ...).

So the following key

```yaml
import: "Import"
```

will be sanitized to

```gleam
t.import_(locale) // "Import"
```

**Note:**
Sanitization happens after resolving [Linked Translations](#linked-translations).
Therefore, links use the key as written in your files (e.g. `@:{general.import}`).
